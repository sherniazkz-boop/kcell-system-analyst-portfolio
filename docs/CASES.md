# Проекты и выбор кейса

## IC Line

**Хакатон · основной кейс.** В командном проекте нужно было объяснять, по каким правилам получилась сумма после изменения договорных условий. Изменение хранится как новая версия с датой начала действия. Пересчёт создаёт новый результат, а карточка суммы показывает формулу и основание расчёта.

Кейс лучше всего показывает путь от бизнес-правила до реализации. «Использовать условие, действующее на дату» становится правилом выбора версии на backend. Frontend даёт форму для новой версии, показывает разницу после пересчёта и объяснение суммы. Конфликт двух версий одного условия с одинаковой датой начала действия даёт проверяемый отрицательный сценарий.

**Командная реализация.** React и TypeScript для экранов, FastAPI для контракта, PostgreSQL для хранения версий и ограничения доступа к данным. Исходный сценарий включает создание версии, пересчёт и просмотр объяснения суммы. На вымышленных данных прошли 44 исходных теста, включая пересчёт после добавления версии и конфликт при повторном вводе.

**Моя роль и разбор.** Участник команды, работал по инструкциям проекта. На защите покажу путь от внесения нового условия до пересчёта и объясню, почему повторное добавление той же версии возвращает конфликт.

## Library Management System

**Университетский проект.** Сервис на Java и Spring Boot использует PostgreSQL. В коде есть REST-операции для книг, авторов и пользователей. В API книг предусмотрены поиск по части названия, фильтр по доступности и постраничная выдача. Регистрация и вход вынесены в отдельные маршруты. Контракт представлен через Swagger/OpenAPI. [Репозиторий команды](https://github.com/azizakuanysh/Final-project_Library-management-system)

**Командная реализация.** Контроллеры, сервисы и репозитории разделяют HTTP-слой, прикладную логику и работу с данными. Этот кейс дополняет портфолио примером API каталога.

**Моя роль и разбор.** Участник команды, работал по инструкциям проекта. На защите покажу, как `GET /api/books?page=0&size=5` передаёт параметры страницы в сервис и репозиторий, а `GET /api/books/search?title=demo` ищет по части названия. [Контроллер книг](https://github.com/azizakuanysh/Final-project_Library-management-system/blob/1d17b1b7702e72efbf452551054af288adbea296/src/main/java/com/example/library/controller/BookController.java), [сервис книг](https://github.com/azizakuanysh/Final-project_Library-management-system/blob/1d17b1b7702e72efbf452551054af288adbea296/src/main/java/com/example/library/service/BookService.java)
